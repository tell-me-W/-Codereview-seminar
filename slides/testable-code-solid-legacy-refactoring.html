SOLID Map

다섯 글자, 다섯 질문

S

책임이 몇 개인가

O

확장 때 기존 코드를 얼마나 건드리는가

L

하위 타입이 약속을 지키는가

I

필요 없는 메서드까지 의존하는가

D

구체 구현을 교체할 수 있는가

Single Responsibility Principle

책임이 많으면 테스트도 무거워진다

비대한 Service

  • 가격 계산
  • 재고 검증
  • 결제 API
  • 저장과 알림

책임 분리

  • `PriceCalculator`는 계산
  • `StockService`는 재고
  • `PaymentClient`는 외부 경계
  • `OrderService`는 흐름 조율
Open-Closed Principle

LSP

부모 타입으로 기대한 동작을 자식이 깨지 않는가?

  • `UnsupportedOperationException` 남발
  • 재사용만 위한 상속 경계

ISP

조회만 필요한데 거대한 Manager 전체를 Mock 하는가?

  • 역할별 Reader / Writer
  • 작은 테스트 의존성
Dependency Inversion Principle

직접 생성하면 대체할 틈이 없다

Before.java고정
public void order(OrderRequest request) {
    PaymentClient client = new PaymentClient();
    client.pay(request.getAmount());
}
After.java교체 가능
private final PaymentProcessor processor;

public void order(OrderRequest request) {
    processor.pay(request.getAmount());
}
