02

Builder
입력을 정리한다

메시지 객체를 오래 들고 다니지 않게 만든다.

Builder

tibrv 메시지에서 도메인 요청으로

Before

  • `msg.getString("ACCOUNT_NO")` 반복
  • 필드명과 파싱 규칙 분산
  • 테스트도 메시지 포맷에 결합
Boundary

After

  • `TradeRequest`로 의미 고정
  • 필수값 검증을 생성 경계에 모음
  • 비즈니스 로직은 명확한 타입 사용
Builder

복잡한 생성 규칙을 한곳에

TradeRequestBuilder.javainput boundary
public TradeRequest from(MessageReader reader) {
    return TradeRequest.builder()
            .accountNo(reader.getString("ACCOUNT_NO"))
            .productCode(reader.getString("PRODUCT_CODE"))
            .quantity(reader.getInt("QTY"))
            .tradeType(TradeType.from(reader.getString("TRADE_TYPE")))
            .build();
}
03

Strategy
분기를 정리한다

타입별 변경이 한 God Class에 모이지 않게.

Strategy

끝없는 if-else와의 전쟁

Before.javaGod Class
if (type == ORDER) {
    order(msg);
} else if (type == CANCEL) {
    cancel(msg);
} else if (type == MODIFY) {
    modify(msg);
}
After.javaDispatcher
MessageHandler handler = handlers.stream()
        .filter(it -> it.supports(context.type()))
        .findFirst()
        .orElseThrow(UnsupportedMessage::new);

handler.handle(context);
Strategy Signal

새 조건이 자주 온다면 후보

Type메시지 타입
Policy업무 정책
Calc계산 방식
Test전략별 검증
04

Pipeline / Chain
흐름을 정리한다

검증, 변환, 처리, 응답이 한 줄에 엉키지 않게.

Pipeline

메시지 처리 단계를 보이게

01

Validate

공통 필드와 상태

02

Build

요청 객체 생성

03

Dispatch

전략 선택과 처리

04

Respond

응답과 후처리

Chain

중간에 멈출 수 있는 흐름

Pipeline

  • 대부분 같은 순서
  • 단계별 테스트
  • 처리 흐름 문서화

Chain of Responsibility

  • Handler가 다음 단계 판단
  • 중복, 권한 실패 조기 종료
  • 대체 응답 가능
05

Facade / Adapter
경계를 정리한다

복잡한 내부와 바꾸기 어려운 외부를 격리한다.

Boundary Patterns

진입점과 번역기를 구분한다

Facade

조회와 검증 묶음을 단순한 호출로

  • 복잡한 하위 시스템
  • 사용자 쪽 이해 비용 감소

Adapter

tibrv, static, 외부 API를 내부 역할로 번역

  • 테스트 대체 가능
  • 외부 변경 영향 축소
Adapter

tibrv를 안쪽까지 끌고 오지 않기

TibrvMessageReader.javaAdapter
public class TibrvMessageReader implements MessageReader {
    private final TibrvMsg msg;

    public String getString(String fieldName) {
        return msg.getString(fieldName);
    }
}
06

God Class는
작게 분해한다

현재 변경에서 가장 아픈 지점 하나부터.

Refactor Order

점진적 분해 순서

tibrv 메시지 읽기를 Adapter로 감싼다.
Builder로 내부 요청 객체를 만든다.
타입별 분기를 Strategy로 뺀다.
긴 처리 흐름을 Pipeline / Chain으로 나눈다.
복잡한 하위 호출은 Facade로 단순화한다.
